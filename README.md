# jev-ja-eval — Jev（TypeSafe AI）を日本語問い合わせデータで評価するキット

株式会社Mojiが公開する、判断専用モデル Jev（TypeSafe AI）を**日本語の業務データで評価するための**データセットとスクリプトです。
Jev に限らず、LLMの構造化出力やルールベースを同じ入力・同じ指標で比較できます。

解説記事: https://www.moji-inc.com/articles/jev-typesafe-ai-speed-cost-comparison

## 中身

| ファイル | 内容 |
|---|---|
| `dataset_ja_inquiries.csv` | 日本語の問い合わせ文 150件（合成データ）。正解ラベル付き |
| `run_eval.py` | Jev / Claude / OpenAI / ルールベース を同一入力で比較し `summary.md` を出力 |
| `make_dataset.py` | データセットの生成スクリプト（ラベルを直したいときはこれを編集） |
| `results_rule_baseline.md` | ルールベース（キーワード一致）の基準値。まずこれを超えるかが最初の関門 |

## データセットの設計

「通常例だけの評価は意味がない」という考えで、判定を間違えやすい入力を意図的に混ぜています。

| category | 件数 | 何を試すか | 例 |
|---|---|---|---|
| normal | 70 | 明確な問い合わせ。緊急案件・長文・業務外を含む | 「二重に引き落とされているようです。返金をお願いします。」 |
| boundary | 22 | 部署が曖昧（請求⇔営業、技術⇔請求 など） | 「有料プランに変更したのに機能が使えません。」 |
| negation | 12 | 否定表現。緊急に見えて緊急でない、その逆 | 「急ぎではありませんが、請求書の宛名を変更したいです。」 |
| insufficient | 9 | 情報不足。確信度で「わからない」と言えるか | 「?」「動きません」「先日の件、どうなりましたか。」 |
| dialect | 8 | 関西弁・博多弁・くだけた口語 | 「請求書の金額、なんかおかしいねんけど見てもらえへん？」 |
| typo | 6 | ひらがな多用・誤変換 | 「せいきゅうしょの金額がちがいます。」 |
| emoji | 6 | 絵文字混じり | 「請求額が倍になってる😱 確認お願いします🙏」 |
| sarcasm | 6 | 皮肉・怒り。要人対応の検出 | 「素晴らしいですね、3回目の二重請求です。」 |
| multi | 5 | 複数部署にまたがる依頼 | 「解約手続きと、最終請求書の発行をお願いします。」 |
| multilingual | 6 | 英語・中国語・仏語混じり | 「Invoiceの金額が間違っています。Please check.」 |

ラベルは3つです。

- `dept`: billing / technical / sales / other（担当部署）
- `urgent`: 0/1（当日中に対応しないと実害が出るか）
- `needs_human`: 0/1（自動応答でなく人が直接対応すべきか）

**注意**: これは合成データです。ラベルは作成者の判断であり、御社の業務ルールとは一致しません。実運用の判断に使う前に、必ず自社データでラベルを付け直してください。

## 測る指標

正答率だけでは足りない、という立場で次を出します。

- 部署・緊急度・要人対応 それぞれの正答率
- **重大誤り**: 緊急案件の見逃し数、要人対応案件の見逃し数
- category 別の部署正答率（境界例・否定表現でどれだけ落ちるか）
- **低信頼度での誤り検知**: 信頼度 <0.7 に落ちた件のうち、実際に誤っていた割合（キャリブレーションの目安）
- レイテンシ P50 / P95
- 推定コスト（API単価のみ。人手確認・再処理は含まない）

## 使い方

```bash
pip install requests anthropic openai

# Jev（TypeSafe API直結）
export TYPESAFE_API_KEY=...
# または Cloudflare Workers AI 経由（AI Gateway のクレジットが必要）
export CF_ACCOUNT_ID=...  CF_API_TOKEN=...
# LLM ベースライン（任意）
export ANTHROPIC_API_KEY=...  OPENAI_API_KEY=...

python run_eval.py --backends jev --dry-run          # 1件だけ投げて接続確認
python run_eval.py --backends jev claude rule        # 本番
python run_eval.py --summarize results.jsonl         # 集計だけやり直す
```

`results.jsonl` に1件ごとの生結果、`summary.md` に集計表が出ます。

## ルールベースの基準値

キーワード一致だけの単純なルールでも部署正答率 73.3%、緊急度 84.7% は出ます。
一方で **緊急案件の見逃しが 33件中19件**、複数部署にまたがる依頼は 5件中1件しか当たりません。
モデルを入れる価値があるかは、この「重大誤り」と「境界例」でどれだけ差が出るかで判断してください。
詳細は `results_rule_baseline.md`。
